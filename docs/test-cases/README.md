# 테스트 명세

기능별로 "무엇을, 왜, 어떤 입력으로, 무엇을 기대하는지"를 적은 문서입니다. 기준은 [업무 명세](../spec.md)입니다.
공통 기준은 [테스트 기준](../TESTING.md), 원본과 달라진 점과 결함 목록은 [알려진 문제](../known-issues.md)에 있습니다.

| 파일                             | 영역                                       | ID 접두사 |
| -------------------------------- | ------------------------------------------ | --------- |
| [base.md](base.md)               | 뼈대: 보안 기본값, traceId, actuator, 시각 | TC-BASE   |
| [api-errors.md](api-errors.md)   | 공통 응답·오류 형식                        | TC-ERR    |
| [auth.md](auth.md)               | 운영자 로그인, 서비스·운영자 토큰, 역할    | TC-AUTH   |
| [application.md](application.md) | 신청 접수, 상태 흐름, 감사 기록            | TC-APP    |

## ID 규칙

`TC-<영역>-<번호 3자리>`. 번호 앞자리는 테스트 종류를 나타냅니다 (HomeFin과 같은 규칙).

| 번호 | 뜻                                                             |
| ---- | -------------------------------------------------------------- |
| 1xx  | HTTP 통합 테스트 (보안 필터·DB 포함, `@SpringBootTest`)        |
| 2xx  | 단위 테스트                                                    |
| 3xx  | 아직 테스트가 없는 항목. `작성 예정` 또는 `자동화 안 함: 사유` |

구현보다 먼저 쓴 행은 최종 번호(1xx·2xx)를 쓰고 자동화 칸을 `작성 예정`으로 둡니다. 구현할 때 테스트 위치로 바꿉니다.

한 번 쓴 ID는 지우거나 다른 테스트에 다시 쓰지 않습니다. 테스트를 없애면 행에 "폐기"와 사유를 남깁니다.

## 표 형식

| 열        | 내용                                                           |
| --------- | -------------------------------------------------------------- |
| ID        | 위 규칙                                                        |
| 분류      | 정상 / 예외 / 경계 / 보안                                      |
| 확인 내용 | 목적과 입력(사전 조건 포함)                                    |
| 기대 결과 | 요구사항 기준 기대 결과                                        |
| 위험      | P0~P3 ([테스트 기준](../TESTING.md#우선순위))                  |
| 자동화    | 테스트 위치, 또는 `자동화 안 함: 사유`                         |
| 관련      | 알려진 문제 번호(원본 참고는 O1~), 확인이 필요하면 `확인 필요` |

**실행 결과는 이 문서에 손으로 적지 않습니다.** 테스트를 실행한 뒤 스크립트가 명세, 테스트 코드, 결과 XML을 대조합니다.

```bash
python scripts/tc_status.py            # 표로 보기
python scripts/tc_status.py --strict   # 불일치·실패·미실행이 있으면 종료 코드 1
```
