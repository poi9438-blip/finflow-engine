# 알려진 문제

FinFlow는 원본(거래·정산 엔진)을 그대로 재현하지 않고, **대출·보증 신청 처리** 서비스로 새로 설계합니다.
그래서 이 문서는 두 부분입니다.

- **원본에서 바꾼 것 (O1~):** 원본 코드에서 확인한 문제 중, 새로 만들 때 처음부터 다르게 만든 것
- **문제 목록 (#1~):** 이 저장소에서 새로 찾은 문제

**확인** 칸은 문제를 어떻게 확인했는지입니다 (코드 / 실행).

## 원본에서 바꾼 것

| 번호 | 원본                                                                                                       | 확인 | 이 저장소                                                                   | 테스트                   |
| ---- | ---------------------------------------------------------------------------------------------------------- | ---- | --------------------------------------------------------------------------- | ------------------------ |
| O1   | `application.yml`에 DB 비밀번호·JWT 비밀키·AES 키 기본값이 있어 `.env` 없이도 약한 값으로 실행됨           | 코드 | 비밀값은 기본값 없이 `.env`에서만 (없으면 compose·서버가 시작하지 않음)     | TC-BASE-301              |
| O2   | `ddl-auto: update` (엔티티를 바꾸면 DB가 몰래 바뀜), 배치 테이블도 `initialize-schema: always`로 자동 생성 | 코드 | Flyway가 테이블을 만들고 Hibernate는 확인만(`validate`)                     | 테이블이 생기는 단계부터 |
| O3   | `X-Trace-Id` 헤더를 형식 확인 없이 로그(MDC)에 넣음, 없으면 접두사 없는 UUID                               | 코드 | 형식(영문·숫자·`._-` 64자 이하) 확인, 없거나 틀리면 `ff-UUID`               | TC-BASE-101~103, 201     |
| O4   | `IllegalArgumentException`·`IllegalStateException`의 메시지를 그대로 응답 (내부 메시지가 나갈 수 있음)     | 코드 | 공개 오류는 `BusinessException`만, 나머지는 500 + 일반 메시지               | TC-ERR-202               |
| O5   | `Exception` 전체를 500으로 처리 → 없는 주소(404)·허용하지 않는 메서드(405)도 500으로 바뀜                  | 코드 | Spring 표준 예외는 원래 상태 코드 유지                                      | TC-BASE-106, TC-ERR-206  |
| O6   | 인증 실패·권한 없음 응답 형식을 따로 정하지 않음 (공통 응답 형식·traceId 없음)                             | 코드 | 401/403도 공통 오류 형식 + traceId (traceId 필터를 보안 필터보다 먼저 실행) | TC-BASE-104              |
| O7   | `open-in-view` 기본값(켜짐) → 요청 끝까지 DB 커넥션을 잡음 (HomeFin #71과 같은 문제)                       | 코드 | `open-in-view: false`                                                       | 트랜잭션 단계에서        |

## 문제 목록

| 번호 | 문제                                                                                                                                                                                                                                  | 확인                            | 상태                                                                                                                        | 수정 PR |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------- |
| #1   | Hibernate 6은 MySQL에서 `@Enumerated(STRING)` 칸을 MySQL ENUM 타입으로 기대해서, VARCHAR로 만든 표와 맞지 않는다고 서버 시작을 거부함. H2 테스트는 표 확인을 꺼 두어서 드러나지 않았음 (`application_id` CHAR(36)도 같은 이유로 거부) | 테스트 (실제 MySQL, TC-APP-203) | 해결 (enum 칸에 `@JdbcTypeCode(VARCHAR)`, 상태를 추가할 때 표를 바꾸지 않도록 VARCHAR 유지, `application_id`는 VARCHAR(36)) | #2      |
| #2   | 서버는 `main()`에서 UTC로 고정하지만 테스트는 `main()`을 거치지 않아 PC 시간대(서울)로 실행됨 → 응답 시각이 `+09:00`으로 나와 운영(`Z`)과 다름                                                                                        | 테스트                          | 해결 (테스트 JVM도 `-Duser.timezone=UTC`)                                                                                   | #2      |
| #3   | 동시 접수 테스트(TC-APP-114)는 두 요청이 실제로는 차례로 처리되는 경우가 많아, 중복을 막는 DB 제약 경로를 확인하지 못함 (그 경로를 지워도 통과)                                                                                       | 변이 검사                       | 해결 (앞쪽 확인을 건너뛰게 한 TC-APP-205 추가)                                                                              | #2      |
| #4   | 접수 응답의 `receivedAt`은 메모리 시각(소수 7자리 이상)인데 DB `DATETIME(6)`은 6자리로 반올림해 저장 → 접수 응답과 조회·재전송 응답의 시각이 다름 (2단계부터)                                                                         | 테스트 (TC-IDEM-101)            | 해결 (시각을 만들 때 마이크로초로 자름)                                                                                     | #3      |
